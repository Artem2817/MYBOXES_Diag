# MyboxDiag · приложение 0.2.2

Стендовая диагностика MYBOX на STM32H743. Только автоматические проверки. Разработано с помощью AI; не является полётной прошивкой.

## Готовые файлы

- `dist/windows-standalone/MyboxDiag-0.2.2-windows-x64.exe` — самостоятельная программа Windows x64.
- `dist/firmware/MyboxDiag-0.2.1-MyboxH743_mini-with-bootloader.hex` — старая Mini, ICM-42688-P + MS5611.
- `dist/firmware/MyboxDiag-0.2.1-MyboxH743_mini_v2-with-bootloader.hex` — Mini V2, ICM-45686 + SPA06-003.
- `dist/firmware/MyboxDiag-0.2.1-MyboxH743_mini_v2_vib-with-bootloader.hex` — Mini V2 Vib, два IMU и два барометра.

Программа 0.2.2 совместима с установленной прошивкой 0.2.1. Для обновления интерфейса достаточно заменить EXE. На сайте опубликованы только полные HEX с загрузчиками и актуальное приложение.

## Быстрый запуск

1. Для первой установки скачайте HEX своей ревизии. Запишите через STM32CubeProgrammer в DFU, затем снимите BOOT0 и перезапустите плату. HEX содержит загрузчик с 0x08000000 и приложение с 0x08020000; сектора параметров исключены. Полное стирание чипа и изменение option bytes не требуются.
2. Запустите EXE, выберите COM-порт и подключитесь. Автоматические проверки начнутся сами; кнопка «Проверить» повторяет цикл.
3. Слева постоянно видна модель платы, справа — IMU, барометры, SD-карта, Flash, USB и OSD. Нажатие выбирает подробности в общей панели, размеры и положение блоков не меняются.

Зелёный статус означает прохождение автоматических проверок данного блока. Красный означает ошибку проверки; жёлтый — замечание, отсутствие свежих данных или недоступность операции. Для IMU/барометра дополнительно контролируется свежесть потока. Итог не подтверждает электрические тракты, которые в автоматический цикл не входят.

## Автоматический цикл

13 определений для всех ревизий; на Mini/V2 применимы 9, на Vib — 13. IMU: ID, настройка и поток. Барометры: ID/CRC, поток и широкий контроль диапазона. OSD: проверка регистра. Flash: чтение первых 4 КиБ приложения. USB: обмен кадрами. SD: доступность и отдельная запись/синхронизация/чтение/сравнение/удаление файла 512 байт.

SD-тест не перезаписывает существующий `MYBOX-DIAG-SCRATCH.bin`: файл создаётся эксклюзивно. При отсутствии карты или невозможности операции проверка не засчитывается успешной. Скорость маленького тестового файла не является паспортной скоростью SD.

Программа последовательно запускает только разрешённые автоматические тесты, дожидаясь ответа и результата каждого. Пункты с перемычками, приборами, поворотами платы и подтверждениями оператора исключены из интерфейса и отчётов. Установленный HEX сохраняет прежний протокол, но такие команды из приложения не отправляются.

## Графики и запись

В меню «•••» → «Показания и график» выберите IMU, барометр или питание. Для IMU показаны X/Y/Z ускорения в м/с² и угловой скорости в °/с. Для барометра — давление в гПа и относительная высота в метрах. Для питания — вольты и амперы. Шкала времени: последние 10/30/60 секунд с нормальным масштабом и текущими значениями над графиком. Пауза останавливает просмотр, запись продолжается. Таблица исходных и пересчитанных значений открывается отдельно переключателем.

Ориентация вычисляется по IMU; курс относительный и может дрейфовать. «Установить ноль» меняет только представление. Оси берутся из аппаратного профиля. При отсутствии свежих измерений модель не дорисовывает движение.

При обрыве программа ожидает ту же USB-плату, учитывает смену COM и сохраняет журнал. Отчёты JSON/HTML и CSV содержат UID и `scope=automatic_checks_only`. Демонстрация в меню «•••» помечена во всём интерфейсе и отчётах; она не является физическим испытанием.

## Проверено

Комплект прошёл программные проверки протокола, отчётов, последовательного автоматического цикла, неподвижности блоков при выборе и единиц графиков. Проверены запуск Windows EXE и демонстрационные отчёты. Пользователь подтвердил стабильную связь Mini после загрузки HEX 0.2.1. Физические результаты конкретных датчиков и SD определяются при запуске на плате.

## Из исходников ПК

Windows: Python 3.11/3.12 x64, затем `pc/start-windows.cmd`. Этот сценарий создаёт отдельное окружение и устанавливает фиксированные зависимости. Для упаковки EXE — `pc/build-windows.cmd`.

Linux:

```sh
python3 -m venv .venv
.venv/bin/pip install -r pc/requirements.txt
.venv/bin/python pc/run.py --demo
```

Используются официальные модули PySide6 Essentials (QtWidgets/QtGui/QtCore), pyserial, pyqtgraph и numpy. Пространственная схема рисуется QPainter, отдельная OpenGL-библиотека не нужна. На Linux нужны системные библиотеки Qt/X11/Wayland; для программной проверки `QT_QPA_PLATFORM=offscreen`.

## Сборка прошивки

Нужен **отдельный** checkout ArduPilot, ARM GCC 10.2.1 (2020-q4-major), Python 3.12 с зависимостями ArduPilot, make, git, rsync. Проверенная платформа: `046cafbceec1a30a202b2eefe64554e5ea54cf01` из MYBOXES_Ardupilot. Установите зависимости платформы по её документации. Все её подмодули должны быть доступны.

```sh
git clone --recurse-submodules https://github.com/Artem2817/MYBOXES_Ardupilot.git /tmp/mybox-diagnostic-platform
git -C /tmp/mybox-diagnostic-platform checkout 046cafbceec1a30a202b2eefe64554e5ea54cf01
git -C /tmp/mybox-diagnostic-platform submodule update --init --recursive
python3 tools/build_firmware.py --checkout /tmp/mybox-diagnostic-platform --jobs 4
python3 tools/verify_hex.py dist/firmware
```

Сценарий копирует только диагностическое приложение в `libraries/AP_HAL/examples/MyboxDiag`, создаёт отдельные HWDEF `MBD_Mini`, `MBD_V2`, `MBD_V2Vib`, отключает постоянное хранилище и функцию записи загрузчика. Исходные определения штатных плат не меняются. Включён `--consistent-build`, задан `SOURCE_DATE_EPOCH`; идентификатор диагностики вычисляется из исходников. В `dist/firmware` сохраняются HEX/BIN/ELF приложения, соответствующие загрузчики, полные HEX, манифест и SHA-256. Для полной побитовой воспроизводимости используйте тот же компилятор и версии подмодулей.

Данные профилей и полная распиновка — `profiles/*.json`, `docs/HARDWARE.ru.md`. Пороговые значения с обоснованием — `config/thresholds.json`; при сборке генерируется `firmware/thresholds.h`. Изменение профиля/порогов требует пересборки.

## Проверки разработки

```sh
PYTHONPATH=pc python3 -m pytest tests -q
python3 -m unittest discover -s tools/site_baseline/tests -p test_build_firmware_site.py
QT_QPA_PLATFORM=offscreen PYTHONPATH=pc python3 pc/run.py --smoke-demo --output examples/local-check
```

Проверяются повреждение/фрагментация кадра, тайм-аут неполного сообщения, переход номера через 2³², совпадение протокола C++/Python, строгие команды, виртуальный последовательный порт, отключение, отчёты, повороты и сохранность каталога сайта.
